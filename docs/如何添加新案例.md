# 如何添加新案例

这份文档是站内「接入指南」（`#/guide`）的离线版，内容一致，适合离线阅读或发给协作者。

## 三条路，三句话

| 方式 | 适合谁 | 怎么开始 |
|---|---|---|
| **A · 上传案例包** | 不写代码 / 只想验证自己的包能不能用 | 右下角「＋ 添加案例」→ 拖入文件夹 |
| **B · 案例包 + 生成脚本** | 本站内置案例的做法（推荐） | `cases/<id>/` 写内容 → `node tools/build-cases.mjs` |
| **C · 直接写插件** | 老办法，仍然可用 | 复制 `assets/cases/_template.case.js`，手改 index.html |

三种方式产出的案例<b>结构完全一致</b>：一份清单（`case.json`）+ 一套示范（`demo/` 里的 html/css/js），在场景页里都长成「专业背景 / 案例流程 / 可运行示范」三个 tab。案例库卡片的封面与摘要由站点侧单独登记（见下文，可选，不进入案例包契约）。

## 案例包长什么样

```
my-case/                     ← 文件夹名建议等于清单里的 id
  case.json                  清单（必需）：元信息 + 专业背景 + 案例流程
  demo/index.html            示范页（整页模式，推荐）
  demo/demo.css              示范页样式
  demo/demo.js               示范页脚本
  README.txt                 说明（可选，给人看的）
```

站点内置的 10 个案例就在 `cases/` 与 `assets/cases/welllog-layer.case.js` 中，随便挑一个抄结构。它们的示范页共用 `tools/demo-base.css` 这套皮肤（`.dhead` / `.dctl` / `.dfig` / `.dnote` 等类），生成脚本会把它复制进每个包的 `demo/demo.css`。

## 方式 A：上传案例包（验证用）

1. 点右上角 **＋ 添加案例**；
2. 把整个文件夹拖进虚线框（或点「选择文件夹」；不支持时点「选择文件」后 Ctrl+A 全选包内文件）；
3. 右侧**逐项校验**，红色必须改，黄色可忽略；点「▶ 试跑示范」可以先看效果；
4. 全绿后点 **校验并添加**：案例立即注册并写入本机 localStorage，页面自动跳到对应场景页。

想拿一个现成的包来测试？打开站内 **案例包（`#/packs`）**，任意一个包都能：

- **▶ 在线试跑**：与上传后完全一致的沙箱渲染；
- **↓ 下载 .zip**：解压后就是一个完整文件夹，可以直接拖回「添加案例」验证导入链路。

> 上传的案例保存在本机浏览器里，换电脑要重新上传。要永久发布给所有人，用方式 B。

## 方式 B：案例包 + 生成脚本（本站内置案例的做法）

### 1. 新建文件夹

在 `cases/` 下新建 `<你的案例id>/`，放入 `case.json`、`demo/`、`README.txt`。

- 文件夹名必须等于 id（kebab-case，全站唯一）；
- `sceneId` 必须是 `assets/data.js` 里已有的场景 id（如 `wo1`）；场景不存在时先在 data.js 对应环节补一条元数据，并加 `demo: true`；
- 三块内容见下面的「契约字段」。

### 2. 跑生成脚本

```bash
node tools/build-cases.mjs          # 生成插件 + 同步皮肤 + 重写 index.html 的脚本块
node tools/build-cases.mjs --check  # 只检查，不写文件
```

它会：

- 把 `tools/demo-base.css` 复制成每个包的 `demo/demo.css`；
- 读 `cases/<id>/case.json` 与包内全部文件，生成 `assets/cases/<id>.case.js`——把清单塞进 `tabs`，把示范文件内联后交给 `CaseDemoHost`，**与「上传案例包」完全同构**；
- 把包清单导出到 `window.CASE_PACKS`，供「案例包」页在线试跑与一键下载 zip；
- 重写 `index.html` 里 `<!-- CASES:BEGIN -->` 与 `<!-- CASES:END -->` 之间的脚本标签。

**`assets/cases/<id>.case.js` 是生成物，不要手改。** 要改内容就改 `cases/` 里的源文件，再跑一遍脚本。

### 3. 两处验收

- 进 **案例库（`#/cases`）**：校验应全绿（id / sceneId / 三块内容 / demo.mount / demo 标记）；
- 进 **案例包（`#/packs`）**：点「下载 .zip」→ 解压 → 拖回「＋ 添加案例」，这条链路跑通说明别人也能导入。

两者都过即接入完成：场景页 tab、面包屑、相关场景、方法反查页条目全部自动出现，不用改别的文件。

### 同 id 覆盖行为

如果上传的包与内置案例**同 id**，校验只给一条**警告**而不是错误：以你上传的这份为准（内置版仍在磁盘上，只是不显示）。在案例库里移除上传版后，会自动回退到内置版。

## 方式 C：直接写插件（老办法）

复制 `assets/cases/_template.case.js` 成 `<id>.case.js`，改 `id` / `sceneId` / `tabs`，然后在 `index.html` 的案例脚本区加一行 `<script>`（必须在 `shell.js` 之前）。适合只有一份 `.js`、不需要独立示范页的情况；`welllog-layer` 就是这个形态。

## 示范的两种模式

**整页模式**（推荐，本站 9 个案例都用它）—— 包里有 `demo/index.html`：

- 整页运行在 **sandbox iframe** 里，样式脚本完全隔离，Canvas / SVG / 第三方库随便用；
- `<link href="demo.css">` 与 `<script src="demo.js">` 会被自动内联，图片等素材的相对路径自动换成内嵌资源——**不需要服务器，双击 index.html 也能跑**；
- 脚本里可以用 `window.caseAsset("core.png")` 取素材地址；
- 注意：**不要用 localStorage / sessionStorage**（沙箱里是 opaque origin，会抛错），也不要发任何网络请求。

**模块模式** —— 只有 `demo/demo.js`（没有 html）：

- 脚本执行后挂进 **Shadow DOM**，上传的 CSS 也注入 Shadow DOM，不会污染主站；样式里可以直接用站点令牌 `var(--jade)` 等；
- 需要导出挂载函数：`module.exports = { mount(root, api), unmount() }`（或 `exports.mount = …` / `window.__CASE_MOUNT__ = …`）；
- `api`：`asset(name)` / `readText(name)` / `list()` / `scene` / `kase` / `onDestroy(fn)`。

两者都没有时，也可以在清单里写 `tabs.demo.builtin = "welllog-layer"` 复用已有示范。

## 可选：案例封面与卡片元数据（站点级）

案例库卡片上的封面与摘要不走案例包契约，由站点侧两个文件提供；场景页仍然只有「专业背景 / 案例流程 / 可运行示范」三个 tab。

| 文件 | 作用 |
|---|---|
| `assets/field/photos.js` | `CASE_COVERS`：案例 id → 封面图 key；`FIELD_PHOTOS`：封面元信息（`src` / `title` / `caption` / `model` / `prompt` / `generatedAt`） |
| `assets/field/field-data.js` | 案例卡片摘要：`library.summary` / `library.kpiMain` / `library.kpiAlt` / `site`，只喂案例库卡片 |

做法：

1. 把封面放进 `assets/field/covers/<案例id>.jpg`（建议 1280×720、JPEG q80），或跑 `python tools/gen-case-covers.py <案例id>` 用 Agnes Image 2.5 Flash 生成；
2. 在 `photos.js` 的 `CASE_COVERS` 里加 `'<案例id>': '<图片key>'`，并在 `FIELD_PHOTOS` 登记模型、提示词、生成时间；
3. 在 `field-data.js` 的 `cases` 里加同 id 的 `library` 与 `site`（可选）；
4. 刷新页面，案例库会自动使用这张封面。

没有封面的案例会退回内联 SVG 占位图形；第三方包不需要这些文件，导入/下载都不会受影响。封面画面要求包含案例元素（工具矩阵、示功图、甘特图等），不出现人物。

## 契约字段

| 字段 | 级别 | 说明 |
|---|---|---|
| `case.json`（文件） | 必填 | 清单，放包根目录 |
| `demo/index.html`（文件） | 可选 | 整页示范，自动内联 css/js 与素材 |
| `demo/demo.js`（文件） | 可选 | 示范脚本；无 html 时为模块模式 |
| `demo/demo.css`（文件） | 可选 | 示范样式（整页模式进 iframe，模块模式进 Shadow DOM） |
| `id` | 必填 | kebab-case，全局唯一 |
| `sceneId` | 必填 | 绑定到 data.js 的场景 id |
| `methods` | 可选 | 数组，如 `["ts","cv"]`；不填继承场景标签 |
| `title` | 必填 | 案例标题 |
| `status` | 建议 | `ready` / `draft` |
| `version` / `updated` | 建议 | 版本与日期 |
| `tabs.background` | 必填 | `judge`（4 格）+ `lede` + `sections[]`（四段式） |
| `tabs.background.sections[]` | 必填 | 每段 `{ no, en, title, html }`，建议恰好四段 |
| `tabs.workflow` | 建议 | `title` / `lead[]` / `stats[]` / `steps[]` / `metrics` / `fails[]` |
| `tabs.workflow.steps[]` | 建议 | 每步 `{ name, do, role, effect, trap }` |
| `tabs.demo` | 可选 | `{ mode, html, js, label, intro, height }` 或 `{ builtin }` |

## 内容怎么写（离线版工具箱）

插件里可以直接调用 `K.*`；**写 case.json 时没有函数可用，手写同样的 HTML 结构即可**（下表的类名就是契约）：

| 想要的效果 | 手写标记 | 插件写法 |
|---|---|---|
| 四段式的一段 | `<div class="sec4"><div class="sn">01<span>PROBLEM</span></div><div class="sec4-body"><h3>…</h3><p>…</p></div></div>` | `K.sec4(1,'PROBLEM','…','…')` |
| 插图 + 图注 | `<div class="figure"><svg …></svg></div><div class="figcap"><b>图 1</b><span>…</span></div>` | `K.figure(svg,1,'…')` |
| 可勾选数据清单 | `<div class="checklist"><div class="cl-head">…<i id="cl-fill"></i>…</div><div class="cl-item">…</div></div>` | `K.checklist(items)` |
| 表格 | `<table class="dtable">…</table>` | `K.dtable(head, rows)` |
| 提示条 | `<div class="callout warn"><span class="ci">注意</span><span>…</span></div>` | `K.callout(text,'warn')` |
| 参考方向胶囊 | `<div class="refs"><span class="ref">…</span></div>` | `K.refs([...])` |
| 难度徽标 / 难度条 | `<span class="dtag" data-d="中">难度 中</span>` / `<div class="meter"><i class="on"></i><i class="on"></i></div>` | `K.dtag('中')` / `K.meter('中')` |

写清单时的两个硬约束：

1. **JSON 必须是合法 JSON**——不能写 `"a" + "b"` 这种 JS 拼接，每个 `html` 值写成一条长字符串；
2. 清单里**不能出现 `<script`**（导入校验会拦），脚本请放在 `demo/demo.js`。

## 颜色规范

浅色主题。案例内写颜色只用两类值：

1. 设计令牌：`var(--jade)` 主色、`var(--clay)` 强调、`var(--c-cv)` 等方法色、`var(--ink-2)` 等文字色；
2. 直接写低饱和的浅色 hex（如 `#e6f1ec`、`#b26a39`）。

**内容区不要写深色背景**（首页的深色带是外壳自己的）。示范页在 iframe 里，可以用 `tools/demo-base.css` 的同一套配色。

## 四个常踩的坑

1. **手改生成物** —— `assets/cases/<id>.case.js` 由脚本生成，改了会在下次构建时被覆盖；改 `cases/` 里的源文件。
2. **sceneId 拼错** —— 不报 JS 错误，案例只是永远不出现；案例库「绑定场景」列会显示 ⚠。
3. **demo 里没有清理** —— 用了 `setInterval` / `window` 级监听，要在 `unmount()`（模块模式）或页面卸载时清掉；整页模式随 iframe 销毁自动清。
4. **在沙箱里用 localStorage / fetch** —— 会抛错或静默失败；示范页请当成「无状态的单页」。

## 删除一个案例

- 内置案例（方式 B）：删掉 `cases/<id>/` 与 `assets/cases/<id>.case.js`，跑一遍 `node tools/build-cases.mjs`；
- 上传的案例：案例库表格里点「移除」，清掉的是本机浏览器存档；
- 插件案例：案例库点「删除」只是隐藏（记入隐藏名单），文件不动；在「已删除的插件案例」区可以恢复。
