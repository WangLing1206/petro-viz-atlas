# 案例示范「AI 作业流」改造规范（v4）

这份文档约束 10 个案例示范页的改造方式。目标不是把图做得更漂亮，而是让读者在示范页里**看见一条智能化的作业流**：现场输入怎样被质控、变成模型能吃的特征/知识、模型怎样训练与推理、输出怎样变成现场动作、人工反馈怎样回到模型。

## 1. 每个示范页必须回答的五个问题

| 阶段 | 页面上的标题 | 必须出现的内容 |
|---|---|---|
| 01 输入 | 采集与质控 | 现场原始数据长什么样；哪些数据不能进模型；质控规则是什么 |
| 02 特征/知识 | 模型看到什么 | 从原始数据到特征/实体/图谱的转换；每一步的物理/业务含义 |
| 03 模型 | 训练与推理 | 真实训练/验证证据（损失曲线、混淆矩阵、校准、覆盖率）；不是静态吹指标 |
| 04 决策 | 置信度与动作 | 阈值、自动/复核/转专家的分流；错误代价；人工在环 |
| 05 闭环 | 价值与回写 | 时间/成本/召回的前后对比；人工确认怎样回写、下一轮怎样重训 |

## 2. 页面结构（照抄抽油机案例）

参考实现：`cases/pump-diagnosis-cv/demo/index.html` 与 `demo.js`。

```
.dhead                 标题 + 4 个统计（判定/置信度/准确率/复核比例）
.dctl                  样本选择 + 参数 + 「▶ 运行全流程」+ 重置
.dflow                 5 个阶段按钮（01 INPUT … 05 LOOP）
.dgrid.c2
  .dcol 左列           贯穿全流程的主画布（曲线/图像/图谱/时间轴）
  .dcol 右列
    .dfig.dstage[data-stage=0..4]   一次只显示一个阶段面板
    .dmodel                          常驻「模型档案」
    .dfig                            常驻「过程日志」(.dtrace)
.dnote                 一句话结论
```

关键类名（已加入 `tools/demo-base.css`，会复制到每个 `demo/demo.css`）：

- `.dflow` / `.dflow button.on` / `.done`
- `.dstage` / `.dstage.on` / `.dstage-lede`
- `.dmodel` / `.dmodel-row`
- `.dtrace` / `.dtrace .t`
- `.dval` / `.dval .k` / `.v` / `.s`
- `.dcm`（混淆矩阵）
- `.dcurve`（训练曲线）
- `.dfeed`（回写按钮）

## 3. 交互要求

1. **阶段轨可点**：点任意阶段切到该面板；已完成的阶段显示 `.done`。
2. **「运行全流程」**：清空日志 → 依次高亮 5 个阶段（约 800 ms/步）→ 每步写一条过程日志 → 结束。
3. **样本切换**：切换样本/参数时，所有阶段面板同步重算；不要只更新一张图。
4. **人工回写**：阶段 05 至少有两个按钮（如「确认正确」「标为误判」），点击后计数并写日志。
5. **过程日志**：每一步写清楚「输入是什么、做了什么、输出是什么」，不要写营销话术。

## 4. 模型要求

- 必须是**在浏览器里真实跑起来的小模型**，不是写死的概率表。允许用合成数据，但要透明标注。
- 训练/验证必须真实计算：训练集/验证集划分、损失或指标、混淆矩阵/校准曲线/覆盖率至少有两样。
- 推理必须用训练出的参数；不要一边展示训练曲线，一边用模板距离冒充模型输出。
- 概率要校准：用标签平滑、温度缩放或 Platt scaling，避免 100% 置信度。
- 必须展示**失败边界**：哪些样本会错、错成什么、低置信度如何处理。

可用的轻量方法（纯 JS，几百行内）：

| 方法 | 适用案例 | 关键实现 |
|---|---|---|
| softmax / 逻辑回归 | 示功图、气测、泄漏事件 | 标准化 + 梯度下降 + 标签平滑 |
| 小样本原型分类 | 套管损伤 | 支持集 → 类原型 → 余弦相似度 → softmax |
| 马氏距离 / 单类模型 | 修井风险 | 正常段估计均值/协方差 → 距离 → 阈值 |
| 分位数回归 | 修井周期 | 3 组 pinball loss 线性模型 → P10/P50/P90 |
| GP + EI | 压裂优化 | 平方指数核 + Cholesky + EI（已有） |
| 动态规划 + 边界概率 | 测井分层 | 滑窗特征 → 边界概率 → DP 分段 |
| 约束推理 + 学习排序 | 打捞选型 | 硬约束过滤 + 逻辑回归排序 + 在线反馈 |
| NLP + 图谱 + CBR | 修井方案 | 词典/正则实体抽取 + TF-IDF 余弦 + 图谱路径 |

## 5. 内容（case.json）要求

- `title` 用「场景 + 从 X 到 Y」或「场景智能X：方法 + 价值」，不要只写方法名。
- `background.lede` 先说现场问题，再说这条流水线怎样嵌进去。
- `background.judge` 四项：任务类型、数据门槛、可见收益、难度；每项都写清「不是什么」。
- `background.sections` 四段仍按 PROBLEM / INTERVENTION / DATA / DIFFICULTY，但第二段必须写**五段流程**，不能只写「用某模型」。
- `workflow.steps` 与示范的 5 个阶段一一对应，每步写 `do / effect / trap`。
- `workflow.metrics` 明确区分「示范合成集指标」与「现场口径」，禁止混用。
- `tabs.demo.intro` 用一句话说清可运行示范里能亲手看到什么过程。
- `tabs.demo.height` 按新页面实际高度设置（一般 980—1200）。

## 6. 验收

```bash
node tools/build-cases.mjs
node tools/check-demo.mjs cases/<id>
node tools/shot.mjs "file:///.../cases/<id>/demo/index.html" out.png 1180 1400 1800
```

- `err` 必须为空；
- 5 个 `.dstage` 都能切换；
- 训练指标、概率、日志随样本变化；
- 截图里没有溢出、遮挡、空白面板；
- 页面上不出现「模板匹配」「静态示意」等与实现不符的字样。
