# 石油智能可视化图鉴

以图形直观呈现石油作业链上「哪一步能被算法替掉、需要什么数据、难在哪里」的静态站点。
纯前端、无后端、可离线：**双击 `index.html` 就能打开**。

## 现在有什么

> v4.0 把 10 个案例示范统一重构为「AI 作业流」：每个案例都能看见 **现场输入 → 特征/知识化 → 模型训练与推理 → 置信度分级与派单 → 人工回写与价值** 这条链，模型在浏览器里真实训练/计算，不再只是展示数据。改造规范见 `docs/AI作业流改造规范.md`。
>
> v3.0 重构了整站视觉与交互（现场记录本 / 测井图版语言），并逐案例修正了专业口径与物理方向；案例契约、路由与离线运行方式保持不变。

- **首屏是 three.js 渲染的三维井场**：`assets/models/wellpad.glb`（glTF 2.0，7376 个三角面、6 种材质）——36 m 高、7 层格构的井架（主腿/横撑/X 斜撑/剪刀撑、二层台、天车台与滑轮组、笼式梯子、工作灯）、桁架式底座与钻台、转盘、绞车、司钻房、猫道与管排、立根、四闸板防喷器、泥浆返出管线、储罐、泥浆泵房、火炬。游车+顶驱做升降动画，钻具随游车伸缩，火炬有火光闪烁；地下是 6 层地层块、带套管与套管鞋的斜井轨迹，另有带等高线的地形网格、勘探区块边界，以及多个含油气砂体与三口水平井。
  4 个状态自动轮播（每 7.6 s 缓动过渡，也可点标签跳，可暂停）：
  ① **井场 WELL PAD**：地面设备为主；② **井筒 WELLBORE**：地层淡出，井眼轨迹点亮、测量脉冲下行；
  ③ **地形 TERRAIN**：回到地表，等高线、测线与勘探区块显形；④ **油气分布 PETROLEUM**：含油气砂体、气顶/油环/水层与井网展开。
  渲染失败时**自动降级**：无 WebGL → Canvas 2D 地震切片场景；再不行 → 静态 CSS 3D 方块。
- **13 个环节 / 61 个候选场景**：地质勘察 → 加工，每个场景带方法标签、难度、数据条件、参考方向。
- **10 个已接入案例**（全部带可运行的五段 AI 作业流示范，纯前端、离线可跑）：
  修井 5 个（方案推荐 / 打捞选型 / 套管损伤 / 风险预警 / 周期预测）+
  测井分层（原有）、采油示功图、气测解释、管道泄漏、压裂优化。
  每个示范都能逐步运行：质控 → 特征/知识化 → 模型训练/推理 → 决策分流 → 人工回写；模型指标（损失、混淆矩阵、校准、覆盖率）在页面里现场计算，不是写死的截图。
- **十种模型，十种真实计算**：5-shot 原型分类（套管）、softmax 回归（示功图/气测/泄漏）、GP + EI（压裂）、分位数回归 + 蒙特卡洛（工期）、逐工序马氏距离（风险）、逻辑回归排序（打捞）、TF-IDF + 图谱 + CBR（修井方案）、滑窗边界概率 + 动态规划（测井分层）——每个案例都写清了「模型负责哪一步、哪一步必须交回人」。
- **案例数据图版（v3.0）**：每个案例的封面不再是通用照片，而是按案例自己的数据现画的 16:9 内联 SVG 图版——打捞工具矩阵、修井甘特、管道负压波、六幅示功图、多臂井径展开、测井曲线族、压裂帕累托前沿……统一纸色 / 墨线 / 黄铜三色，离线可看。
- **案例内的进阶可视化（v3.2）**：示功图七维特征平行坐标（与概率行联动）、套管四类损伤指纹小多图（点击切换类型并定位）、修井工期 CDF（计划滑杆联动）、压裂参数敏感性龙卷风图（扰动超压标红）——都直接长在案例的「可运行示范」里。
- **可交互作业链地图（v3.0）**：首页把「按环节 / 矩阵 / 星图」三个视图收进一个控制台，点环节即时预览 5 个场景；另有按「数据形态 × 团队技能 × 目标」的起步推荐器。
- **场景星图 · 联动分析台（`#/explore`）**：61 个场景按「环节 / 方法 / 难度 × 数据源 / 案例覆盖」四种布局动画重排；在散点上拖框刷选，左侧环节、右侧方法×环节热图与场景清单同步收窄；支持自动重排演示。
- **两条检索路径**：按环节（作业链）逐级下钻，或打开「场景星图」把 61 个场景按环节 / 技术 / 难度重排；另有「方法 × 环节」矩阵做交叉核对。
- **案例包库（`#/packs`）**：9 个包可在站内**在线试跑**、**下载 .zip**，解压后拖回「＋ 添加案例」即可导入。
- **接入系统**：案例以「清单 + demo」的包形式接入，上传 / 生成插件两条路效果一致。

## 案例库（`#/cases`）怎么读

页面按「现场视图」组织，不再是一张校验表：

- **库头**：内容封面 + 4 个统计（案例 / 覆盖场景 / 内容封面 / 可运行示范）；
- **筛选**：按环节、技术标签、关键词搜索（案例 id、标题、场景、现场、方法都能搜到）；
- **卡片**：每张卡有与案例内容对应的图片、环节色条、上线状态、两项核心成效、数据源与现场规模；
- **工程校验**：原来那张契约校验表收进页面底部的「工程校验与接入状态」折叠区，逐项明细仍在，不挡内容。

### 案例内容封面

封面由 Agnes Image 2.5 Flash 按案例内容生成，画面直接包含该案例的元素：

- 打捞选型 → 打捞工具按矩阵排列 + 工具匹配表；
- 修井周期 → 七道工序的甘特条、P50/P80 区间与蒙特卡洛分布；
- 抽油机诊断 → 六幅示功图与工况标注；
- 管道泄漏 → 管道走向图、压力/流量曲线与报警点；
- 测井分层 → 多条测井曲线、分层界线与井筒剖面；
- 套管损伤 → 多臂井径仪器与套管成像展开图。

图片为 2K 生成后裁成 1280×720，放在 `assets/field/covers/`；`assets/field/photos.js` 的 `CASE_COVERS` 负责案例 id → 图片映射。没有封面的案例退回内联 SVG 占位图形，第三方包不受影响。

重新生成：`python tools/gen-case-covers.py --force`。

## 打开与运行

不需要构建、不需要服务器：

```
直接双击 index.html
```

> **看到的还是旧版？** 本页所有资源都带 `?v=` 版本号，入口 `index.html` 自身可能被浏览器缓存。
> 按 `Ctrl+Shift+R` 强制刷新，或在地址栏把 `index.html` 改成 `index.html?v=3` 再回车。
> 新版的三处特征：首屏是深色三维井场 + 两行标题「一条作业链 / 61 个可被算法接手的位置」；首屏下方是一个可切换「按环节 / 矩阵 / 星图」的作业链控制台；页脚写 `v4.0 · 2026-11-01`。
> 如果看到的是「深色 + 线框方块 + 红色提示条」，说明当前浏览器没有可用的 Canvas 2D，场景会退化成静态示意图，其余功能不受影响。

如果要做开发期自检（可选，需要本机有 Node 18+ 与 Chrome）：

```bash
node tools/build-cases.mjs        # 案例包 → 插件（改完 cases/ 后跑一遍）
node tools/build-cases.mjs --check
node tools/test-import.mjs        # 导入链路端到端（校验→添加→示范→刷新持久化→同 id 覆盖→回退→同场景多案例）
node tools/test-routes.mjs        # 全路由巡检：JS 错误 / console 报错 / 结构计数
node tools/test-cases.mjs         # 9 个示范页逐个自检：JS 错误 / 图表数 / 控件数 / 说明文字
node tools/build-model.mjs        # 重新生成井场模型（改模型后跑这个）
node tools/check-demo.mjs cases/workover-plan-kg   # 单个示范页自检（也可用 EXTRA=… 跑自定义断言）
node tools/shot.mjs "file:///…/index.html" out.png 1440 2000   # CDP 整页截图（含沙箱 iframe）
```

## 兼容性说明（改版时的三条底线）

1. **案例契约不变**：`case.json` 字段、`demo/` 文件约定、三个 tab 的结构都没动。第三方包（如 `firstbreak-pick-case`）导入后的渲染路径与旧版一致。
2. **依赖全在本地**：`assets/vendor/` 内置 three.js r128 与 GLTFLoader（约 700 KB），不联网、无 npm 运行时；模型以 base64 内联成 `wellpad.glb.js`，因此 `file://` 下用 `GLTFLoader.parse(ArrayBuffer)` 解析，**不需要 XHR/fetch**（浏览器会拦本地文件请求）。
   健壮性：WebGL 探测失败或模型解析失败都会自动降级（Canvas 2D → CSS 3D），页面不会白屏；`prefers-reduced-motion` 只降速；每秒检查一次帧计数，环境吞掉 rAF 会自动重启；离屏/切后台/点「暂停」才停。

## 换掉首页的 3D 模型

`assets/models/` 里有同一份模型的三种形态：

| 文件 | 用途 |
|---|---|
| `wellpad.gltf` | 标准 glTF（缓冲以 data URI 内嵌），可直接拖进 Blender / 三维查看器检查 |
| `wellpad.glb` | 二进制 glTF，供 http 环境或其它工具使用 |
| `wellpad.glb.js` | `window.WELLPAD_GLB = "…base64…"`，`file://` 下实际加载的那份 |

换模型的两条路：

1. **改生成脚本**：编辑 `tools/build-model.mjs` 里的几何（梁/圆柱拼装），跑 `node tools/build-model.mjs`，页面刷新即生效；
2. **用自己的模型**：把一个 glTF/GLB 转成 base64 写进 `wellpad.glb.js`（`assets/models/README.md` 有一行命令），或改用 `GLTFLoader.load('assets/models/xxx.glb')` 并在本地起个 http 服务。

要求：单位是米、原点在井口正下方地面、y 轴向上；可动部件命名为 `travelingBlock` 会被自动识别做升降。
3. **纯静态可离线**：所有资源相对路径加载，`file://` 下可用；案例示范跑在 sandbox iframe 里，与主站样式互不影响。

## 添加一个案例（最短路径）

```bash
# 1. 复制一个现成的包，改 id / sceneId / 内容
cp -r cases/workover-plan-kg cases/my-case
# 2. 生成插件（同时同步示范皮肤、重写 index.html 的脚本块）
node tools/build-cases.mjs
# 3. 打开 #/cases 看校验是否全绿；再到 #/packs 下载 zip 拖回「添加案例」验证
```

细节见 `docs/如何添加新案例.md`。
